## 发布与验证节奏（跨版本 · 当前生效）

沿用自 V1 阶段（2026-10-06 决定），适用于 V2 / V3。

**决定**：**提审发布（Chrome / Edge）、全量验证（`pnpm test:e2e` 全量）、`pnpm compile` 统一推迟到 V3 完成之后**一次性执行，不再作为每个版本的收尾动作。

| 项目 | 何时做 | 说明 |
|------|--------|------|
| 改动所需的最小验证 | 每次改动 | 如本次仅跑 `pnpm test` 单测；不为「顺手跑全量」付出成本 |
| `pnpm compile` | V3 完成后 | 与发布闸门一起跑 |
| `pnpm test:e2e` 全量 | V3 完成后 | 依赖真实 Ollama + `wxt build`，见 [decisions-v1.md](./decisions-v1.md)「本地 E2E 运行须知」 |
| 提审发布 | V3 完成后 | 上架材料 `docs/store-listing.md` 届时按最终权限 / 单一用途复核 |

**理由**：V2 / V3 仍会改动消息协议、权限与目录结构，过早提审会产生重复的验证成本与上架材料维护；`docs/store-listing.md` 的权限用途说明必须与最终 `manifest` 一致，早提交即早返工。

**风险与对策**：推迟期间不做全量回归，可能积累隐性问题 → 以 `git` 分支 / 提交粒度隔离，V2 / V3 各阶段改动保持可独立回滚；发布闸门清单见 [architecture-v2.md](./architecture-v2.md)。

## V2 摘要 / 聊天 · 范围与决策（2026-10-07）

**范围**：网页摘要（一键）+ 单页网页问答（多轮、流式、可中止）；上下文可在「选区 / 当前页正文」间切换；复用同一 BYOK Provider，不新增模型接入。

**不做**：PDF / 视频、RAG 向量检索、跨标签页知识库、云同步、搜索增强、邮件回复、Agent 自动化（后置 V2.5+ / V3）。

| 决策 | 结论 |
|------|------|
| Feature 隔离 | 新建 `features/chat/`；独立消息前缀 `chat:*` + Port `dualmind-chat`；**不复用** `translateSession` / `translate:*` |
| 共享提取层 | 新建 `features/page-content/`，从 `immersive/segmenter.ts` 抽出「语义正文提取 + 标题/段落分块 + 截断预算 + 选区上下文」，沉浸译改为引用该模块（**先做等价重构，既有单测作护栏**） |
| storage | 新增 `local:chatPrefs`（上下文范围等）与 `local:chatSessions`（**全局**会话列表，每条含 `pageUrl` / `pageTitle` / `messages` / `updatedAt`） |
| 会话容量 | 上限 **50 会话 / 每会话 200 条消息**，超限**淘汰最旧**（`chrome.storage.local` 有配额，必须先定清理策略）；逻辑在 `shared/storage/chatSessions.ts`（纯函数 + 单测） |
| 上下文预算 | `chatPrefs.maxContextChars`（默认 12000）按段累加截断，不切半段；首段即超预算时至少保留一段，避免空上下文 |
| 上下文读取时机 | **首次提问时**读取并缓存于内存（不落 storage）；切换范围立即按新范围重读；面板提供「重新读取」手动刷新。读取失败不阻塞对话，退化为纯对话并如实提示 |
| 内容页解析（工作台） | `chat:context` / `chat:page-info` **不**盲信 `active: true`。全页工作台本身是扩展标签页，活动页常为 `chrome-extension://`。统一走 `resolveContentTab`（`features/chat/resolveContentTab.ts`）：① 活动页为 http(s) → 用之；② 否则回退该窗口**最近一次活动过的可读内容 tab**（内存 Map，按 `windowId`）；③ SW 冷启动无缓存时，同窗口按 `lastAccessed` 挑最近可读页。UI 展示「绑定页」标题 / host。权限**不扩大**。Side Panel 与工作台共用同一解析 |
| 会话切换与在途流式 | 新建 / 切换会话**中断**在途流式；所有异步回写先比对会话 id，**迟到回包直接丢弃**（防止流式增量写进新会话） |
| 会话与页面绑定 | 重开旧会话后追问，取的是**当前内容页**正文（经 `resolveContentTab`，非「当前活动标签」字面义）。若会话已记录 `pageUrl`、**已有历史消息**且未被标记 `allowCrossPage`，发送前比对当前内容页（`chat:page-info`，不触发内容脚本，比较时**忽略 hash**）：不一致则弹确认条，**并列显示会话来源页与当前页地址**，提供三个动作 —— 「仍要继续」（本次发出）/「本会话不再提示」（置 `session.allowCrossPage = true` 后发出，此后不再检查）/「取消」（不发且**把提问还回输入框**，不丢草稿）。确认任一路径都会**先把当前页写回会话来源**（`pageUrl` / `pageTitle`），避免随后上下文读取失败时回退到旧来源而反复弹确认。新建会话 / 首轮提问不做这次探测（零额外往返） |
| 右键菜单与 disabledHosts | 三个右键菜单项（`dualmind-translate` / `-immersive` / `-chat-summarize`）在内容脚本被禁用的站点上**置灰**（`contextMenus.update({ enabled: false })`），由 Background 在 `tabs.onActivated` / `tabs.onUpdated` / `storage.onChanged` 时重算。理由：`documentUrlPatterns` 无法表达「除 disabledHosts 外的所有站点」，而无效点击只会得到空洞的失败提示；站点禁用能力不应被绕过 |
| 右键菜单入口 | 「总结本页」由 Background 写入信箱 `local:chatPending`（消费即清空 + TTL 30s），**由常驻的 `WorkbenchApp` 消费**并切到网页助手 Tab 再下发给 `ChatPanel`。理由：`sidePanel.open()` 与面板挂载存在竞态，runtime 广播不可靠；且 `ChatPanel` 仅在网页助手 Tab 挂载，用户停在翻译 Tab 时会漏事件。仅 Side Panel 消费，避免全页工作台抢走动作 |
| 正文不落 storage | 页面正文只在会话内保存已发送的上下文片段 / 引用，不作为独立快照持久化 |
| 权限 | **不扩大**：复用现有 `<all_urls>` content script，不引入 `scripting` / `activeTab` |
| 入口 | Side Panel / 全页工作台「网页助手」Tab；右键菜单「总结本页」；（可选）快捷键 |
| 与既有 Feature 关系 | 复用同一 BYOK Provider（`shared/llm`）与 Side Panel；**不新增模型接入**，不改动 `translate` / `immersive` 行为（`page-content` 抽取为等价重构） |

## V2 页面悬浮入口 · 决策（2026-10-07）

**背景**：V1.5 的右下角悬浮按钮是**沉浸译专属**入口（见 [decisions-v1.md](./decisions-v1.md)）。V2 起演进为**多动作入口**：单个按钮 hover 展开「沉浸译 / 总结本页 / 后续功能」，避免每加一个能力就往页面上多挂一个按钮。

| 决策 | 结论 |
|------|------|
| 形态 | 单个主按钮，**默认收起**、不铺开菜单、不主动打扰（延续 V1「不默认开启强打扰悬浮球」）。取**浅色极性**的品牌标记：浅蓝圆底 + 深蓝双 D（`assets/logo.svg` 的内联副本；path 与渐变色值由 `features/page-fab/dom.test.ts` 与资产**逐字比对**，不引 `web_accessible_resources`）。底板：资产圆角方块 → 圆；**鼠标档静止收成 12px 贴边窄把手**、移入 / 展开 / 拖拽 / 有状态时滑出为完整圆形，**触屏档不启用把手**（无悬停可唤出）始终全宽正圆 |
| 辨识度 | 不用「半透明浅色玻璃底」——那种底自身没有对比边界，落在浅底页面上会糊掉。浅色按钮改由**深色发丝环（`box-shadow` 第一层）+ 加深投影**拉开边界（白环在白底页面上等于没有） |
| 状态表达 | **不染按钮底色**（底色不承载状态语义），状态走发丝环之外的**语义色环**：busy 品牌蓝 `#1b7fd1` + 脉冲动效（颜色已被语义占用，「进行中」交给动效）、active 绿、warning 琥珀、error 红；细节文案仍在动作项（「翻译中 x/y」「N 段未翻译」） |
| 展开交互 | hover 意图（停留 150ms）展开；面板**粘住、不因移出而收起**，关闭路径是：再点按钮（切换）/ 点面板外 / 面板头部 `×` / `Esc` / 滚动。点击主按钮 = 切换展开状态，键盘聚焦即展开（省一次 Enter）—— 触屏与键盘的主路径。因面板不再「移出即收」，指针穿过按钮与面板之间那 8px 空隙不再有风险，**原先用于桥接命中区的伪元素已删除**（它正是为「移出即收」打的补丁） |
| 架构 | 新建 `features/page-fab/`（入口壳 + 动作注册表）：壳**不认识**任何具体能力，各 feature 挂载时 `registerAction`；新增能力不改入口壳，能力之间零耦合 |
| 拖动 | 按住可拖动（pointer capture，拖出窗口仍跟随）；位移阈值（鼠标 4px / 触屏 10px）区分「拖拽 / 点击」，判定为拖拽后吞掉随后的 `click`，避免「拖完手一松」误触发动作 |
| 落点 | 松手**就近吸附左 / 右边缘**（x 由贴边推导）+ 夹回视口；只持久化 `{ side, y }` 到 `local:pageFabPos`，**全局共享**一份（不按站点区分） |
| 静止形态（鼠标档） | 静止时收成 **12px 宽、贴住视口边缘**的窄把手（`peekWidth`）：外缘与视口边缘对齐、不越界。把手是一块**独立形状**（圆角只留页面内侧），**不显示品牌标记** —— 刻意不采用「把圆形裁一刀」：裁出来的弧在贴边处宽度趋近 0，读起来像「图标破了」，还要额外维护一份「把被裁掉的字形挪回可见区」的平移量（`GLYPH_SHIFT_VB` / `GLYPH_OPTICAL_PX` 已随之删除）。**可辨识性不靠宽度而靠三层对比**（见「把手可辨识性」一节） |
| 把手可辨识性 | 首版是「8px + 近白浅蓝渐变 + 常态 0.42 不透明度」，三重降对比叠在一起，在白底页面上几乎与背景同色，实机反馈「太不明显、注意不到」。改法：① 宽度 8 → **12px**（够放下抓手点，也更好点中；再宽就开始挤正文）；② 底色改成**品牌蓝半透明实底**（`rgba(27,127,209,0.2)`）＋页面内侧一条 **2px 品牌蓝实边**，不靠页面底色衬托，白底 / 深底都读得出轮廓；③ 把手内竖排**三个抓手点**（通用「可抓 / 可展开」符号）—— 空白窄条读起来像装饰，不像入口；④ 常态不透明度 **0.42 → 0.85**。第 ④ 条是关键：**浅色填充再叠一层透明度会直接化进白底**，只加宽、只加色都救不回来；「让位」交给滚动档的 0.15 表达。四项各有单测锁住（`dom.test.ts` 的「把手自带对比」与「把手内有抓手点」、`attention.test.ts` 的常态下限） |
| 几何按指针类型分档 | 尺寸 / 把手宽 / 拖拽阈值收敛为 `FabGeometry`（`position.ts`），由 `matchMedia('(pointer: coarse)')` 选：**鼠标 40px + 把手 12px + 阈值 4px**；**触屏 48px + 把手宽 = 按钮宽（不启用把手）+ 阈值 10px**。触屏没有悬停、只能盲点，十几像素的把手点不中（Material 建议触控目标 ≥48dp），因此触屏**始终全宽正圆**；手指按下抖动也远大于鼠标，阈值须放宽。用 `matchMedia` 而非 UA：桌面触屏 / 平板外接鼠标时 UA 会说谎。指针类型变化（接/拔鼠标）时重算几何与落点 |
| 注意力分级 | 入口默认「存在但不抢注意力」：常态不透明度 **0.85**、滚动中 **0.15**（停止滚动 600ms 后恢复）、指针移入或键盘聚焦时 **1**。常态值以「一眼能看见」为准、**让位交给滚动档表达**：静止形态只有 12px 宽，视觉权重本来就低，而**浅色填充再叠一层透明度会直接化进白底**（0.42 是实机反馈偏淡的旧值，下限 0.8 有单测锁住）。优先级（高→低）：**已展开 / 有状态 > 滚动 > 常态** —— 有活在跑或报错时必须完整可见，**滚动不得把反馈藏起来**。整档收敛为**单一数值**（`attention.ts` 的 `resolveOpacity`）写进 `--dm-pf-idle-opacity`，避免多条 CSS 选择器互相覆盖 `opacity`；只降不透明度、**不改 `visibility`**，否则淡出时连 `pointerenter` 都收不到。滚动中不触发 hover 起意（否则停滚瞬间凭空弹菜单）；**面板展开时滚动会把它收起** —— 面板是 `position: fixed`，页面滚它却钉在原地会一直挡着正文（旧版靠「移出即收」掩盖了这点，粘性面板必须显式处理） |
| 形态切换（把手 ⇄ 圆形） | 「是否滑出成完整圆形」由 `attention.ts` 的 `resolveRevealed` 与不透明度**同源**算出，写进 `data-reveal`。四种情况滑出：**指针移入**（不然用户面对 12px 把手不知道能点）、**面板展开**（面板与提示都挂在按钮上，把手宽度撑不起）、**拖拽中**（手里抓的是完整按钮，中途缩回去像抓空了）、**有状态**（否则「出错了」只有把鼠标移上去才看得见）。滚动不参与：滚动中本来就该让位，那时也没有指针停在入口上 |
| 面板对齐 | 壳（`.dm-pf`）有**显式尺寸**（宽 = 把手宽、高 = 按钮边长），且贴边侧边缘与视口边缘对齐；按钮是它的绝对定位子元素、**朝页面内侧生长**（贴右 `right: 0` / 贴左 `left: 0`）。于是面板 / 提示挂在贴边侧就天然整块在屏内 —— 旧版的 `--dm-pf-menu-dx` 横向回推补偿已删除。壳的宽度必须显式：它没有在流子元素可撑开收缩宽度，塌成 0 会让面板贴错位置 |
| 展开方向 | 按钮在上半屏向下展开，否则向上展开；贴右向左伸展、贴左向右伸展，保证菜单不出视口 |
| 错误反馈 | 动作 `onClick` 抛错由入口壳统一 `formatErrorForUi` + 一次性浮层提示；动作内部不必自己弹提示 |
| 站点禁用 | 沿用 `settings.disabledHosts`：命中则**整个内容脚本不注入**（划词与悬浮入口一起关掉） |
| 与 V1.5 的关系 | 沉浸译**入口形态**由专属 FAB 演进为共享入口的一个动作；`immersive:*` 消息、右键「翻译整页」、侧栏控制区链路**不变**；[decisions-v1.md](./decisions-v1.md) 记录的 FAB 状态优先级（running > active > idle；error 覆盖 warning；title 优先未翻译段数）继续适用 |
| 网页总结入口 | 悬浮入口「总结本页」复用右键菜单链路：内容脚本发 `chat:summarize-page` → Background **在手势有效期内** `sidePanel.open()` + 写 `local:chatPending`，由常驻 `WorkbenchApp` 消费（同上表「右键菜单入口」）。手势约束见 [decisions-v1.md](./decisions-v1.md)「侧边栏 open 的手势窗口」 |

## V2 悬浮入口 · 开关与粒度（2026-10-07）

**背景**：入口此前只有「站点禁用」一条路可关，而它会把划词翻译一起关掉；用户「只是不想看见悬浮球」时没有可用的开关。同时入口需要一个**自查即走**的能力（当前站点不想再看到它）。

| 决策 | 结论 |
|------|------|
| 两条列表语义必须分开 | `settings.disabledHosts` = **整站停用**（划词 + 入口都不注入）；`settings.pageFabHiddenHosts` = **只隐藏入口**（划词、整页翻译、右键菜单照常）。二者判定函数也分开（`isHostDisabled` / `shouldShowPageFab`），不做参数化合并 —— 合并后调用方很容易传错列表，而症状是「用户抱怨划词坏了」 |
| 入口级开关 | 新增 `settings.pageFabEnabled`（默认 `true`）。关掉只跳过 `mountPageFab`，**不跳过** `mountImmersive` / `mountChatContext` |
| 隐藏入口 ≠ 关掉能力 | `mountImmersive` 除注册入口动作外，还承担右键「翻译整页」/ 侧栏指令的消息监听与 `autoTranslate`，因此入口隐藏时**仍必须挂载**（`fab` 参数改为可选）。曾按「入口隐藏就整体跳过」实现，会静默弄坏整页翻译 —— 用户只是不想看悬浮球，却把功能一起关了 |
| 粒度 = 站点级 | 与 `disabledHosts` 同一套**精确 hostname** 匹配（复用 `isHostDisabled` 语义，不误伤子域名）。不做「单页面 URL 级」：URL 级需要额外的归一化规则（query / hash / SPA 路由），而这些正是最容易做出「我明明关过这页了」的地方；且 hostname 列表可直接复用既有 `parseHosts` 与 Options 表单 |
| 文案必须与粒度自洽 | 因粒度是站点级，菜单文案为「**本站**不再显示」而非「本页」——否则用户以为只关了当前这一页，下次打开同站其它页面会当成 bug |
| 菜单内的关闭操作 | 面板底部常驻「隐藏悬浮按钮」（`data-empty` 只看 feature 注册的动作数，壳自带操作不计入）；点击后**原地换内容**到二级视图（「本站不再显示」/「所有页不再显示」/「返回」）。不侧向飞出：飞出面板要另算一套横向位移（贴左 / 贴右都要推），视口边缘极易被裁。**面板收起 / 重新展开时必须把视图重置回动作列表**，否则下次展开会停在隐藏确认页上 |
| 隐藏自身的时序 | 先收起面板 → 隐藏按钮与面板（`data-hidden`，用 `visibility` 而非 `display`，保住 wrap 盒子好让提示有锚点）→ **保留 toast** → 提示走完再 `ui.remove()`。若直接 `ui.remove()`，提示与入口一起消失，用户无法分辨「隐藏成功」与「点坏了」；「所有页不再显示」之后页面上再无入口，提示里的恢复路径是唯一线索 |
| 恢复路径 | 入口隐藏后**只能**在 Options 恢复（两个控件：显示开关 + 站点列表）。因此两条提示文案必须写明去哪恢复，属于功能的一部分而非装饰 |
| 不即时生效 | 全局关掉 / 新增站点后，**其它已加载的标签页要刷新才消失**（内容脚本已注入）。要即时需 Background 广播到所有标签页，属额外范围，暂不做 |

## V2 悬浮入口 · UI 显示逻辑改版（2026-10-07）

**背景**：入口的功能（多动作注册表、拖拽吸附、隐藏开关、状态反馈）都已齐备，但**显示逻辑**读起来不像成熟产品：静止时是一个「被切掉一角的圆」（像图标坏了）、面板是一列 172px 宽的纯文字、且鼠标扫过就会弹、移开就收。本轮**只改 UI 显示逻辑，能力与契约一行不变**（`PageFabAction` / `registerAction` / 隐藏开关 / 位置持久化 / 状态 tone 全部照旧）；上表「形态 / 展开交互 / 静止形态 / 形态切换 / 面板对齐」各行已按本轮结论改写，这里只留**取型理由**与**随之删掉的支撑件**。

| 决策 | 结论 |
|------|------|
| 取型 | 采纳 **Edge / Arc / Kimi 的「边缘把手 peek → 滑出」**（静止只留一块窄把手，指针移入才滑出完整按钮）+ **Intercom / Monica / Material 3 FAB 的「点击展开卡片」**（品牌头部行 + 明确关闭）。否决 ① **径向扇形菜单**：放不下动作项的 `status` 文案（「翻译中 3/12」），而动作数只会继续涨；否决 ② **横向胶囊展开条**：贴边位置横向空间最紧，正是最需要它的地方没空间 |
| 面板结构 | 自下而上：**品牌头部行**（小标记 + 「DualMind」+ `×`）→ 动作区（每行 ≥44px：图标 + 主文案 + 状态读数，展开时**按序号错峰 20ms 淡入**）→ 分隔 → 底部次要区（「隐藏悬浮按钮」）。头部解决「面板长得像网页自家浮层、用户不敢点」的归属感问题；主文案超出时省略号截断、**状态读数不截断**（它是读数，截了就没意义） |
| 品牌标记的第二处引用 | 面板头部的小标记与主按钮**同源**（都是 `BRAND_MARK_SVG`，同一份几何），只把渐变 id 由 `dmTile` 换成 `dmMark`：同一 shadow root 里出现两个同名 id 时 `url(#dmTile)` 只命中第一个，两份定义虽相同，但那是靠巧合成立 |
| 动效 | 把手展开 / 收起用宽度与圆角过渡（`0.16s`），品牌标记交叉淡入（缩放会经过「畸形的中间态」）；面板从按钮那一角「长出来」；动作项错峰入场。全部在 `prefers-reduced-motion: reduce` 下退化为瞬时切换 —— **不影响功能**，reveal 只是一次宽度切换 |

**「点击 = 切换」的连带修正**：`pointerdown` 不再收起面板 —— 按下与点击分不开，按下就收会被紧随的 `click` 再展开，表现为「点一下没反应」；改为**位移超过阈值、真的开始拖**时才收。

**改版同时删掉的历史包袱**（都是旧形态的支撑件，形态换了就该一起走）：
- `parkRatio` / `parkOffset`（「藏进视口外 1/3」的偏移模型）→ 换成 `peekWidth` + `hasPeek`；
- `GLYPH_SHIFT_VB` / `GLYPH_OPTICAL_PX`（把被裁掉的字形挪回可见切片的平移量）→ 静止形态不画字形，不需要补偿；
- `--dm-pf-menu-dx` / `MENU_INSET`（把出界的面板推回视口内的补偿）→ 壳已贴边，面板天然在屏内；
- 桥接按钮与面板之间空隙的 `::after` 伪元素 → 面板粘住后，穿过空隙不再会误收起；
- `MENU_CLOSE_DELAY_MS`（pointerleave 的收起宽限期）→ 没有「移出即收」了。

**坐标系的坑（改这块最容易翻车的地方）**：拖拽坐标是**按钮（`size` 宽）的左边缘**，落点坐标是**壳（`peekWidth` 宽）的左边缘**，两者相差 `size - peekWidth`。拖拽全程只跟踪按钮（那才是用户看见、抓住的东西），换算成 `left` 样式时由 `mount.ts` 的 `shellLeftFor` 补差。`position.test.ts` 用同一套矩阵跑鼠标 / 触屏两档，专门锁这两个坐标系。

**测试与文档**：`dom.test.ts` 锁「壳有显式尺寸 + 按钮锚在贴边侧 + 把手是独立形状 + 把手自带对比与抓手点 + 已删的补偿量不得回流」；`position.test.ts` 锁两套坐标系与把手宽下限；`attention.test.ts` 锁形态切换的四个条件与常态不透明度下限；`e2e/immersive.e2e.ts` 的拖动用例改为量测「贴左时把手 `x = 0` 且宽 < 高」。

**同日后修正 · 把手可辨识性**：改版首版的静止把手是「8px + 近白浅蓝渐变 + 常态 0.42 不透明度」，三重降对比叠在一起，在白底页面上几乎与背景同色 —— 实机反馈「太不明显，用户注意不到」。修正为 **12px + 品牌蓝半透明实底 + 页面内侧 2px 实边 + 三个抓手点**，常态不透明度抬到 **0.85**（让位交给滚动档的 0.15）。**教训**：窄 ≠ 弱，把手的「轻」应该靠**面积小**表达，不能同时把对比度和不透明度也压掉 —— 尤其「浅色填充 × 不透明度」在纯白页面上是乘法关系，两者一叠就直接越过「看得见」这条线。四项改法各有单测锁住，见上表「把手可辨识性」。
